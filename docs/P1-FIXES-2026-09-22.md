# Исправления P1 из аудита 2026-09-20

## A1 — ложные препятствия от камеры

Цветовой детектор формирует гипотезу. Для передачи этой гипотезы в навигацию
и добавления занятой ячейки карты теперь требуется конечная дальность,
полученная от лидара в соответствующем направлении. Когда подтверждения нет,
расчётная дальность по положению цветного пятна в кадре не используется.
Изображение камеры продолжает передаваться, независимое обнаружение препятствий
лидаром сохраняется.

Уже сохранённые ложные отметки не удаляются автоматически. Новое обследование
из дашборда отправляет `clearMap: true` и очищает прежнюю карту перед построением
новой; пользовательские данные не удаляются при обновлении программы.

Регрессионный тест использует сохранённый кадр пустого пола из аудита и
синтетические измерения: свободное пространство, отсутствующий лидар и
подтверждённое препятствие на расстоянии 0,8 м. При отсутствии лидара RGB-цвет
сам по себе не является основанием для объезда. Это не стереозрение и не
распознавание препятствий любой высоты; объекты вне плоскости лидара требуют
отдельного источника глубины.

## A2 — обследование вне жизненного цикла миссии

Команда `start_mapping_survey` проходит через сервис миссий и gateway.
Она получает ID, сохраняется в журнале, занимает робота и отслеживается
дашбордом через тот же механизм, что и обычный маршрут. Повторная отправка
после потери ACK использует прежний ID. Отмена остаётся в состоянии
`cancelling` до подтверждения контроллером; до этого другая миссия не запускается.

ID передаётся в `runtime_command.txt`, сохраняется в сгенерированном `route.csv`
и в памяти контроллера, включая перестроение обследования. Ошибка генерации,
записи или чтения маршрута останавливает обследование и сохраняет состояние
`route_failed`. Повтор уже отменённого обследования не возобновляет движение.
Запуск обследования через обычное обновление сцены запрещён.

Старые ручные команды обследования без `mission_id` больше не выполняются.
Для запуска следует использовать дашборд/сервис миссий. Порядок запуска проекта
и команды npm не менялись. Для применения изменений к контейнерной установке
нужно пересобрать образы `frontend`, `route`, `gateway` и `simulator` согласно
используемому Compose-профилю.

## Проверка

Успешно выполнены `npm run lint`, `npm test` (275 тестов, включая один
локальный диагностический тест аудита), `npm run build`, `npm run webots:build`
и расширенный `npm run test:services`. После последней правки сериализатора
дополнительно прошли его тесты, интеграционный тест обследования и ESLint
изменённых JavaScript-файлов.

Проверки запускаются локально; логи находятся в `output/audit-2026-09-20/p1-*.log`.
Расширенный `npm run test:services` проверяет обследование через реальные
отдельные процессы, WebSocket, HTTP и файлы обмена. Feedback контроллера в этом
тесте синтетический, физическая симуляция не запускается.

Docker Engine во время проверки недоступен (`dockerDesktopLinuxEngine` отсутствует).
Физическое выполнение в контейнере после этих изменений пока не проверено.
Проблемы P2 из исходного аудита остаются отдельными задачами.
