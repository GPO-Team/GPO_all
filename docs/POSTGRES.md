# PostgreSQL для GPO

Схема из предоставленного DBML переведена в PostgreSQL SQL:
`docker/postgres/init/001-schema.sql`. Создаются 16 таблиц, внешние ключи,
ограничения CHECK, три ENUM, уникальные индексы и роли `admin`, `group_leader`, `user`.
Пользователи, пароли пользователей и разрешения не заполняются.

## Запуск

Нужен запущенный Docker Desktop в режиме Linux containers.
В корне проекта создайте `.env` на основе `.env.example`, если его ещё нет.
Укажите собственный `POSTGRES_PASSWORD`; остальные значения по умолчанию:

```dotenv
POSTGRES_DB=gpo
POSTGRES_USER=gpo
POSTGRES_PASSWORD=your-private-password
POSTGRES_PORT=5432
```

```sh
npm run db:up
npm run db:check
npm run db:psql
```

`db:up` ждёт готовности сервера. В psql команда `\dt` покажет таблицы,
`SELECT * FROM roles;` — начальные роли, `\q` завершит сеанс.
`db:psql` использует имя пользователя и базы `gpo`; при изменении этих настроек:

```sh
docker compose -f compose.postgres.yaml exec postgres psql -U YOUR_USER -d YOUR_DATABASE
```

Подключение из DBeaver/pgAdmin или локального backend:
хост `127.0.0.1`, порт `5432`, база `gpo`, пользователь `gpo`, пароль из `.env`.
Формат строки подключения:
`postgresql://gpo:<URL-encoded-password>@127.0.0.1:5432/gpo`.
При занятом порте измените `POSTGRES_PORT`, например на `5433`.
Пароль не следует помещать в переменные `VITE_*`: они доступны браузеру.

## Контейнеры и данные

```sh
npm run db:logs
npm run db:stop
```

Данные находятся в именованном томе `postgres_data` и сохраняются после остановки
или пересоздания контейнера. Остановка через `db:stop` не затрагивает другие сервисы.
Не используйте `down -v`, если данные нужно сохранить.

Базу можно включить в общий Compose-проект:

```sh
docker compose -f compose.yaml -f compose.postgres.yaml up -d
```

Для общего стека также нужны настройки gateway из основной инструкции проекта.
В его Docker-сети PostgreSQL доступен по адресу `postgres:5432`.

SQL из `docker-entrypoint-initdb.d` выполняется только при первом запуске с пустым
томом — это поведение [официального образа PostgreSQL](https://hub.docker.com/_/postgres).
Правки SQL и переменных `POSTGRES_*` не изменяют уже созданную базу;
для существующей базы нужны отдельные миграции / `ALTER ROLE` при смене пароля.

## Решения при переносе схемы

- Имена таблиц и столбцов приведены к нижнему регистру без кавычек.
- Цикл `users.group_id` / `user_groups.leader_id` сохранён: сначала создайте
  пользователя без группы, затем группу с ним как руководителем, затем обновите `group_id`.
- Ошибочная последняя связь `SCENARIOS.id <? SCENARIOS.user_id` исключена;
  `scenarios.user_id` ссылается на `users.id`.
- Удаление связанных записей блокируется внешними ключами; каскадное удаление не задано.
- Проверка роли руководителя и принадлежности к группе остаётся задачей backend,
  как указано в исходной схеме. `updated_at` имеет DEFAULT, но не обновляется автоматически.

Этот шаг создаёт базу. Текущие React/bridge-сервисы пока не обращаются к ней:
авторизация, API и перенос файлового хранения требуют отдельной реализации на backend.
