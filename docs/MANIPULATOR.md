## Что реализовано

Манипулятор использует моторы и контакты Webots. Код исполнения не меняет translation объекта. Connector удалён из сцены и адаптера: удержание обеспечивают только физические контакты пальцев. Поле `attached` сохраняет прежний формат API и обозначает владение грузом, а не физическое крепление. Куб 15 см, масса 250 г и ручка шириной 25 мм сохранены.

Локальный `webots/protos/YoubotManipulation.proto` основан на официальной модели R2025a с сохраненными лицензией, массами, инерциями и лимитами. Пальцы оборудованы bumper TouchSensor, приводы — обратной связью усилия/момента. TCP находится в подвижном toolSlot. Ракурс камеры приближен к роботу.

Кинематика учитывает реальные оси и смещения пяти суставов. IK выбирает допустимую конфигурацию рядом с измеренной. Суставы и пальцы движутся синхронно по плавному профилю времени симуляции. Подход и укладка разделены на промежуточные позы. Для DEMO_BOX используется постоянный наклон кисти -2.25 рад, чтобы при повороте руки коробка сохраняла вертикальное положение.

После захвата DEMO_BOX робот поднимает коробку над бортами, поворачивает руку и ставит её на заднюю левую часть платформы. Площадка расширена до 32 × 38 см и оборудована задним и боковыми бортами. Положение центра груза относительно базы: X = −7 см, Y = +7.5 см.

Перед отпусканием контроллер сопоставляет реальные точки контакта коробки и робота на высоте площадки, проверяет вертикальность и устойчивость. После разблокировки захвата пальцы раскрываются, рука отводится через верхнюю переднюю точку и складывается в стороне от груза. Только после подтверждения опоры и парковки руки разрешается поездка. Груз едет на платформе с открытым, разблокированным захватом.

В точке доставки база останавливается. Рука повторно захватывает коробку с платформы, поднимает над бортами, переносит вперёд и опускает на пол. Завершение требует подтверждённого отпускания и возврата руки. При запуске без команды робот остаётся на месте.

Для команды `pick_place` восстановлены обработчики запуска/отмены и телеметрия
этапа, удержания и контактов пальцев. В сцену возвращён `PICK_BOX`, на который
ссылается эта команда. Кисть компенсирует поворот первого сустава, сохраняя
ориентацию пальцев относительно коробки. Усилие каждого пальца для этого груза
массой 40 г ограничено 2 Н: прежние 20 Н вызывали колебания контактов и срыв захвата.

Захват требует совпадения контактных точек груза с каждым пальцем, bumper-сигналов, положений пальцев и допустимого расстояния до TCP. Контакты идентифицируются через узлы устройств пальцев. Пробный подъём должен поднять груз и сохранить подтверждение в течение 0.25 с. Потеря контакта или уход объекта из захвата останавливает операцию. Отпускание требует измеренного контакта с полом, допустимых высоты, вертикальности и скоростей. Подтверждённая опора сохраняется при неизменной неподвижной позе, если Webots перестал выдавать контактные точки; движение груза отзывает подтверждение.

Навигационные плечи строятся через граф видимости с проверкой зазора вокруг ограниченных зон. Перенос использует поступательное mecanum-движение при сохранении ориентации базы, чтобы избежать резкого разворота с грузом. Скорость с грузом ограничена 0.06 м/с, ускорение колес с грузом — 1 рад/с². Свежие lidar traces проверяются на препятствия в коридоре движения, собственный переносимый объект исключается. Обнаруженное препятствие приводит к остановке, а не к рискованному обходу с выдвинутой рукой.

## Запуск

После обновления сцены и контроллера перезапустите Webots: уже запущенный процесс не подхватит новый EXE и PROTO.

```powershell
npm run webots:build
npm start
```

В панели автопереноса укажите X/Y и запустите миссию. В блоке состояния доступны измеренные и целевые углы, положение кисти, контакты, усилия, ошибки и восстановление. Команда запуска пересобирает изменённый контроллер и PROTO внутри контейнера.

## Проверки

```powershell
npm test
npm run lint
npm run build
npm run test:webots
npm run test:simulation
npm run test:manipulator
```

`test:manipulator` запускает отдельный экземпляр настоящего Webots с временной сценой, текущим production-контроллером и независимым каталогом состояния. Рабочие данные симулятора не используются. Проверяются движение руки, физический подъем, удержание во время транспортировки, размещение, отпускание и устойчивость после завершения.

Варианты приемки (после команды очищайте соответствующие переменные окружения):

```powershell
$env:MANIPULATOR_SMOKE_MODE="realtime"
npm run test:manipulator
Remove-Item Env:MANIPULATOR_SMOKE_MODE

$env:MANIPULATOR_SMOKE_CANCEL_STAGE="transporting"
npm run test:manipulator
Remove-Item Env:MANIPULATOR_SMOKE_CANCEL_STAGE

$env:MANIPULATOR_SMOKE_STATIC_ZONE="1"
npm run test:manipulator
Remove-Item Env:MANIPULATOR_SMOKE_STATIC_ZONE
```

Также поддерживаются `MANIPULATOR_SMOKE_CANCEL_STAGE=grasping`, `MANIPULATOR_SMOKE_DESTINATION_X/Y`, `MANIPULATOR_SMOKE_RESULT_SUFFIX` и `MANIPULATOR_SMOKE_TIMEOUT_MS`. Отчеты сохраняются в `output/manipulator-smoke-result*.json`.

Добавлены `MANIPULATOR_SMOKE_CANCEL_STAGE=approaching_object`,
`MANIPULATOR_SMOKE_MISSING_GRIP=1` (удаляет ручку только из временной тестовой
сцены) и `MANIPULATOR_SMOKE_ATTEMPTS=10` (каждая попытка запускает новую сцену).
Сводка повторяемости: `output/manipulator-repeat-summary.json`. Ненулевая ошибка
любого полного цикла делает итог проверки неуспешным. После завершения
проверяются ещё две секунды времени симуляции: база и объект должны оставаться
неподвижны. Для настоящих испытаний на Windows сначала выполните
`npm run webots:build`, чтобы тест не использовал старый EXE.

Приёмка платформенного цикла:

```powershell
$env:MANIPULATOR_SMOKE_CONTAINER="1"
$env:SIMULATOR_GPU="1" # при доступном WSLg; иначе не задавать
npm run test:manipulator:contacts
```

Проверяются физический захват, контакт с площадкой, разблокировка, устойчивое движение с отпущенной коробкой, повторный захват и выгрузка. Отчёт содержит стадии, положения базы и коробки, признаки удержания и длину поездки на платформе. Полный тест `npm run test:container` дополнительно проверяет этот цикл через сервисы и последующую доставку PICK_BOX.

## Ошибки и восстановление

При отказе база останавливается, рука получает удержание измеренной позы. Ресурс робота остается занят, если груз удерживается, находится на платформе либо рука не находится в парковочной конфигурации. При отмене с грузом на платформе поездка прекращается, коробка повторно захватывается и выгружается перед базой. При ошибке выгрузки ресурс сохраняется в состоянии восстановления. При отмене во время подхода кисти рука сначала открывается и возвращается.

Возобновление требует подтверждённого захвата либо опоры груза на платформу; перед поездкой снова проверяются опора и положение руки. При ошибке без груза восстановление возвращает руку в парковку. Каждый новый отказ получает recoveryEpoch, поэтому backend различает повторные попытки даже если краткий RUNNING не попал в polling. Request ID повторной доставки сохраняется идемпотентным внутри одной попытки.

## Границы текущего сценария

### Отмена PICK_BOX с грузом

После ошибки или отмены маленького груза владение рукой и базой сохраняется, пока груз может оставаться в захвате. Миссия переходит в `holding_for_recovery`, а новые миссии блокируются. Кнопка «Безопасно выгрузить» повторяет попытку опустить груз на свободный участок пола под ним. Если место занято, траектория руки пересекает препятствие или показания захвата недостоверны, робот продолжает удержание.

При выгрузке контроллер проверяет контакт объекта с полом, его высоту и неподвижность. После подтверждения опоры он снимает давление на пол движением руки вверх на 5 мм и открывает пальцы; управление освобождается после измеренного открытия захвата и складывания руки. Повторная доставка запроса отмены не перезапускает уже начавшуюся выгрузку. Автоматическая выгрузка использует плоский пол текущего мира (`z=0`) и известную collision-геометрию Box/Sphere/Cylinder; для неизвестной опоры сохраняется состояние восстановления.

Перед стационарным переносом проверяются место размещения и выборочные положения звеньев/груза вдоль траектории суставов. Эти консервативные проверки также выполняются при изменении положения руки; тесная сцена может потребовать дополнительного свободного пространства.

Для DEMO_BOX время подъезда и перевозки рассчитывается по длине маршрута, поворотам и ограничениям скорости. Отдельный контроль останавливает навигацию после 60 секунд симуляции без измеренного перемещения или поворота. Команда переноса имеет устойчивый ключ публикации: повтор после сбоя журнала не запускает физическую доставку снова, включая записи старого формата без ключа.

Поддерживается demo-box с заданной ручкой и размещение на горизонтальном полу. Захват произвольных предметов, поверхности разной высоты, полная 3D-проверка столкновений всех звеньев и автономное повторное нахождение упавшего груза требуют отдельных моделей и планировщика. После потери удержания система не продолжает перевозку без физического восстановления захвата.

Путь вокруг статических зон проверяется с консервативным зазором; при новых препятствиях с грузом применяется остановка. Помимо Windows, физический цикл проверен в Linux-контейнере Webots R2025a через Xvfb/Mesa: измеренное движение руки 2,60 рад, подъем около 7,8 см, ошибка размещения около 2 мм.

При мобильном захвате угол кисти пересчитывается относительно фактического
поворота базы после подъезда к объекту. Для параллельных пальцев учитывается
эквивалентность оси захвата через 180°, чтобы не упираться в предел запястья.
Это устраняет остановку `stage_timeout` при захвате PICK_BOX с другой стороны
после доставки DEMO_BOX. Проверены обратная кинематика в Linux/GCC и Windows/MSVC,
затем полный GPU-стек Docker/WSLg (RTX 3060 Laptop): большой груз доставлен в
`(2, 0.6)` с ошибкой около 0,6 мм, малый — в `(2, 2)` с ошибкой около 12 мм.
В том же прогоне проверены камера, W3D, восстановление сервиса миссий после
SIGKILL и отмена после перезапуска Webots. Лог прогона:
`output/full-container-verification-fixed.log`.

Для независимой проверки физики в уже собранном образе `gpo-webots:local` задайте `MANIPULATOR_SMOKE_CONTAINER=1` и выполните `npm run test:manipulator`. Этот режим не требует установленного Webots на хосте и удаляет только собственный временный контейнер. Для проверки всего стека используйте `npm run test:container`.
