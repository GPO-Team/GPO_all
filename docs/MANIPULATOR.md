# Физический манипулятор Webots

## Что реализовано

Перенос demo-box выполняется моторами и контактами Webots. Код исполнения не меняет translation объекта и не создает невидимую фиксацию. Куб 15 см и массой 250 г сохранен; сверху добавлена физическая ручка шириной 25 мм, которую охватывает штатный захват.

Локальный `webots/protos/YoubotManipulation.proto` основан на официальной модели R2025a с сохраненными лицензией, массами, инерциями и лимитами. Пальцы оборудованы bumper TouchSensor, приводы — обратной связью усилия/момента. TCP находится в подвижном toolSlot. Ракурс камеры приближен к роботу.

Кинематика учитывает реальные оси и смещения пяти суставов. IK выбирает допустимую конфигурацию рядом с измеренной. Суставы и пальцы движутся синхронно по плавному профилю времени симуляции. Подход и укладка разделены на промежуточные позы. Для этого объекта используется наклон кисти -2.8 рад: он обеспечивает достижимость подхода, подъема и рабочего контакта дистальных площадок пальцев.

Захват подтверждается двусторонним контактом и положением рабочей точки относительно объекта. Пробный подъем должен поднять груз и сохранить подтверждение в течение 0.25 с. Потеря контакта или уход объекта из захвата останавливает операцию. Отпускание разрешается после подтверждения опоры, скорости и положения; раскрытие пальцев и устойчивость укладки проверяются отдельно.

Навигационные плечи строятся через граф видимости с проверкой зазора вокруг ограниченных зон. Перенос использует поступательное mecanum-движение при сохранении ориентации базы, чтобы избежать резкого разворота с грузом. Скорость с грузом ограничена 0.06 м/с, ускорение колес — 4 рад/с². Свежие lidar traces проверяются на препятствия в коридоре движения, собственный переносимый объект исключается. Обнаруженное препятствие приводит к остановке, а не к рискованному обходу с выдвинутой рукой.

## Запуск

После обновления сцены и контроллера перезапустите Webots: уже запущенный процесс не подхватит новый EXE и PROTO.

```powershell
npm run webots:build
npm start
```

В панели автопереноса укажите X/Y и запустите миссию. В блоке состояния доступны измеренные и целевые углы, положение кисти, контакты, усилия, ошибки и восстановление. Если запущен контейнерный симулятор, пересоберите его образ: локальный PROTO теперь входит в Docker-пакет.

## Проверки

```powershell
npm test
npm run lint
npm run build
npm run test:webots
npm run test:simulation
npm run test:manipulator
```

`test:manipulator` запускает отдельный экземпляр настоящего Webots с временной сценой, текущим production-контроллером и независимым каталогом состояния. Рабочие данные симулятора не используются. Проверяются движение руки, физический подъем, удержание во время транспортировки, размещение, отпускание и устойчивость после завершения.

Варианты приемки (после команды очищайте соответствующие переменные окружения):

```powershell
$env:MANIPULATOR_SMOKE_MODE="realtime"
npm run test:manipulator
Remove-Item Env:MANIPULATOR_SMOKE_MODE

$env:MANIPULATOR_SMOKE_CANCEL_STAGE="transporting"
npm run test:manipulator
Remove-Item Env:MANIPULATOR_SMOKE_CANCEL_STAGE

$env:MANIPULATOR_SMOKE_STATIC_ZONE="1"
npm run test:manipulator
Remove-Item Env:MANIPULATOR_SMOKE_STATIC_ZONE
```

Также поддерживаются `MANIPULATOR_SMOKE_CANCEL_STAGE=grasping`, `MANIPULATOR_SMOKE_DESTINATION_X/Y`, `MANIPULATOR_SMOKE_RESULT_SUFFIX` и `MANIPULATOR_SMOKE_TIMEOUT_MS`. Отчеты сохраняются в `output/manipulator-smoke-result*.json`.

Физически проверены обычный цикл в fast и realtime, другая точка с отрицательным Y, отмена до захвата, отмена с грузом и обход четырех физических стен ограниченной зоны. Типичный измеренный подъем — 7–8 см; ошибки размещения в выполненных прогонах — несколько миллиметров. Это результаты конкретных сценариев, а не гарантия такой точности для произвольных объектов и окружений.

## Ошибки и восстановление

При отказе база останавливается, рука получает удержание измеренной позы. Ресурс робота остается занят, если груз удерживается либо рука не находится в парковочной конфигурации. При отмене с грузом выполняются опускание, раскрытие и возврат руки. При отмене во время подхода кисти рука сначала открывается и возвращается.

Возобновление переноса требует подтвержденного физического удержания; оно сначала повторно проверяет подъем и только затем разрешает перевозку. При ошибке без груза восстановление возвращает руку в парковку. Каждый новый отказ получает recoveryEpoch, поэтому backend различает повторные попытки даже если краткий RUNNING не попал в polling. Request ID повторной доставки сохраняется идемпотентным внутри одной попытки.

## Границы текущего сценария

Поддерживается demo-box с заданной ручкой и размещение на горизонтальном полу. Захват произвольных предметов, поверхности разной высоты, полная 3D-проверка столкновений всех звеньев и автономное повторное нахождение упавшего груза требуют отдельных моделей и планировщика. После потери удержания система не продолжает перевозку без физического восстановления захвата.

Путь вокруг статических зон проверяется с консервативным зазором; при новых препятствиях с грузом применяется остановка. Помимо Windows, физический цикл проверен в Linux-контейнере Webots R2025a через Xvfb/Mesa: измеренное движение руки 2,60 рад, подъем около 7,8 см, ошибка размещения около 2 мм. Контейнерные GPU-прогоны не выполнялись.

Для независимой проверки физики в уже собранном образе `gpo-webots:local` задайте `MANIPULATOR_SMOKE_CONTAINER=1` и выполните `npm run test:manipulator`. Этот режим не требует установленного Webots на хосте и удаляет только собственный временный контейнер. Для проверки всего стека используйте `npm run test:container`.
