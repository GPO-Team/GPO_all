## Результат и цель

Цель: воспроизводимый физический PICK → TRANSPORT → PLACE для DEMO_BOX от UI до
подтверждённой разгрузки, без изменения координат груза и скрытого крепления.

**Спринт не закрыт.** Внесены исправления безопасности, обратной связи, отмены и
тестов. Настоящий Webots доступен, физические испытания выполнены. Стабильный
полный перенос DEMO_BOX получить не удалось: сохраняется `grip_lost`. Успешные
unit-тесты не подменяют этот результат. Состояние восстановления намеренно не
освобождает робота после потери захвата.

Работа выполнена в существующей рабочей папке. До начала уже было много
незакоммиченных изменений, в том числе в контроллере, UI, сервисах и lock-файле.
Они сохранены; commit и push не выполнялись. Зависимости не устанавливались и
не менялись в рамках этой работы.

## Обнаруженные проблемы

1. Адаптер выполнял `wb_connector_lock`, а блокировка Connector засчитывалась
   как `grip_evidence`. Это нарушало требование переноса только пальцами.
2. Bumper-сигналы не доказывали, что оба пальца касаются именно груза.
3. Отпускание допускалось при отклонении высоты до 7 см от исходной высоты,
   без измеренного контакта с полом и проверки угловой скорости/вертикальности.
4. После пропадания контактных точек у неподвижного объекта уже поставленный
   груз мог получить `placement_failed`, хотя рука вернулась в парковку.
5. `allows_navigation` разрешал перевозку по имени стадии, без повторной
   проверки измеренной парковки руки и открытия пальцев. На ошибке service
   мог одновременно выдавать `stop_base` и `request_navigation`.
6. Команда `set_manipulator_pose` доходила до контроллера, но игнорировалась.
   Соответствующая функция была только объявлена.
7. В тестах simulation сохранились старые ожидания: груз на платформе считался
   прикреплённым, использовалось устаревшее смещение платформы и ожидалось
   удержание вместо безопасной выгрузки при отмене.
8. Старый EXE в рабочей папке не соответствовал исходникам. Первый физический
   запуск до пересборки проверял прежнее поведение.
9. Форма «Автоперенос объекта» позволяла отправлять новое задание при занятом
   роботе. Backend блокировал его, но UI оставался доступным.
10. Карточка восстановления говорила «Удержание объекта» даже при явном
    `attachmentEvidence=false`.
11. Физика без Connector выявила реальный срыв захвата; этот дефект остаётся
    главным препятствием закрытию спринта.

## Как исполняется цикл и что останавливает его

UI отправляет прежнюю команду `transfer_object`. Сервис миссий сохраняет её
идентичность и исключает конкурирующую миссию. Gateway публикует команду в
изолированный от сервиса файловый интерфейс. Контроллер строит подъезд, решает
IK и закрывает пальцы. Положительный захват требует контактов обоих пальцев
именно с грузом, фактических положений пальцев и допустимой близости к TCP.

После пробного подъёма предусмотрены укладка на платформу, измеренное
подтверждение опоры, отпускание, парковка руки, перевозка, повторный захват и
разгрузка. Только фактические этапы контроллера передаются через телеметрию и
сервис миссий в React; прогресс не рассчитывается таймером браузера.

Перед поездкой проверяются отсутствие груза в захвате, подтверждение платформы,
исправность датчиков, измеренная парковка суставов и раскрытие пальцев. Отсутствие
lidar запрещает движение; существующие свежие трассы проверяют коридор движения.
Ограничения скорости базы и ускорения колёс сохранены.

Перед отпусканием требуется зарегистрированный контакт с полом, высота центра
куба 0.075 м с допуском 6 мм, вертикальность Z > 0.97, линейная скорость < 0.025
м/с, угловая < 0.15 рад/с и ошибка X/Y < 5 см. Устойчивая опора подтверждается
0.25 с измерений. Если контактные точки исчезли, подтверждение сохраняется лишь
при той же неподвижной позе (смещение не более 3 мм); движение отзывает его.
Раскрытие и возврат руки проверяются отдельно. Smoke дополнительно проверяет
две секунды симуляции после терминального состояния.

При `grip_lost`, неверных датчиках, препятствии, недостижимости или таймауте
база останавливается. Владение сохраняется, если груз мог остаться в захвате,
на платформе или рука не припаркована. Потерянный груз не объявляется успешно
доставленным. Продолжение при недостоверном захвате запрещено. Восстановление
не раскрывает пальцы без опоры.

## Настоящий Webots и UI

Использован установленный Windows Webots R2025a и текущий production-контроллер.
Каждый smoke создавал отдельную копию мира/PROTO/EXE, временные WEB_STATE_DIR и
MISSION_STATE_DIR, свободные порты. Пользовательские сцены и данные не
использовались для физической приёмки. Сброс между десятью попытками выполнялся
новым процессом и новым миром, без изменения координат груза во время миссии.

В итоговой серии 6/10 попыток физически прошли захват, подъём примерно на 20 см,
укладку, перевозку на площадке и повторный захват; затем груз терялся при
перемещении руки к выгрузке. Остальные остановились при первом подъёме.
Это частичные результаты, не успешные полные циклы. Всего в трёх формальных
сериях выполнено 30 независимых попыток; успешных полных циклов — 0.

В браузере запущен отдельный UI + четыре сервиса + настоящий Webots. Из формы
отправлена DEMO_BOX в `(2, -0.6)`. Проверено отображение реально полученных
stage/progress/missionId, ошибки grip_lost, контактов `[0,0]`, отсутствия
подтверждённого удержания, блокировки Resume и нового запуска. Отмена из UI
дошла до контроллера; при потерянном захвате робот сохранил безопасное владение.
Сверены ID, статус и код ошибки в HTTP-ответе backend и robot_state.json.

## Оставшиеся ограничения и следующая работа

Главный незакрытый дефект — физический захват DEMO_BOX. Connector скрывал
ненадёжность контактов. Короткие вертикальные движения дают отдельные успешные
подъёмы, но не воспроизводимый полный цикл. Замедление движения не устранило
проблему и было отменено; исходный профиль скорости сохранён. Требуется дальнейшая
калибровка геометрии TCP/контактных поверхностей
и нагруженной траектории с регистрацией контактов на каждом шаге. Увеличение
допусков или имитация крепления не являются исправлением.

Не подтверждены: 10 успешных полных циклов, устойчивая разгрузка DEMO_BOX,
последующая навигация именно после DEMO_BOX, безопасная отмена при перевозке
этого груза и полное восстановление после его потери. Препятствие и разные
координаты запускались, но преждевременный отказ не позволяет засчитать их
физическую приёмку. Идемпотентность и рестарт покрыты существующими интеграциями;
полный новый физический сценарий с принудительным перезапуском не заявляется.

## Запуск и демонстрация преподавателю

Нужны Node.js 22.19+, установленные зависимости, Visual Studio C++ Build Tools
и Webots R2025a. В этой среде зависимости уже присутствовали.

1. В корне проекта выполнить `npm run webots:build`.
2. В первом терминале выполнить `npm run bridge`.
3. Во втором терминале выполнить `npm run dev`.
4. Открыть `http://127.0.0.1:5173/dashboard`.
5. В Webots открыть `webots/worlds/youbot_only.wbt` и включить Run. После
   изменения EXE/PROTO нужен перезапуск мира/контроллера. При нестандартном
   WEB_STATE_DIR у Webots и bridge должно быть одно значение.
6. Для проверенной демонстрации маленькой коробки открыть справа «Телеметрия» →
   «Манипулятор · перенос объекта», выбрать PICK_BOX, задать
   `X=0.4, Y=0.1, Z=0.04`, нажать «Взять и перенести». Наблюдать физический
   захват, разгрузку и статус завершения. Это отдельный проверенный сценарий.
7. Для испытания большого груза слева раскрыть «Перенос объекта» →
   «Автоперенос объекта», задать `X=2, Y=0.6`, нажать «Захватить и перенести».
   Это команда полного цикла, **её успешное завершение сейчас не гарантировано**.
8. При grip_lost показать справа реальную ошибку и измерения. Не пытаться
   объявить миссию завершённой или принудительно освободить руку. Для следующего
   независимого испытания перезапустить тестовый мир, а не перемещать груз в
   ходе миссии.
9. Для воспроизведения приёмки без пользовательских данных:

```powershell
npm run webots:build
npm run test:manipulator:contacts
$env:MANIPULATOR_SMOKE_ATTEMPTS="10"
npm run test:manipulator:contacts
Remove-Item Env:MANIPULATOR_SMOKE_ATTEMPTS
$env:MANIPULATOR_SMOKE_MISSING_GRIP="1"
npm run test:manipulator:contacts
Remove-Item Env:MANIPULATOR_SMOKE_MISSING_GRIP
```

Возврат ненулевого кода при неудачном полном цикле является правильным
результатом проверки, а не поводом отключать её.

Семантика измерений сверялась с первичными источниками Webots:
[Supervisor / contact points](https://github.com/cyberbotics/webots/blob/R2025a/docs/reference/supervisor.md),
[Motor / position and force feedback](https://github.com/cyberbotics/webots/blob/R2025a/docs/reference/motor.md).
