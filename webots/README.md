# Webots Integration

`GPO-main` теперь содержит рабочий контур для `KUKA youBot` в `Webots`.
Контроллер и его модульные тесты собираются как C++20; прежних C-исходников в этом контуре нет.

## Что используется

- Мир: `webots/worlds/youbot_only.wbt`
- Контроллер: `webots/controllers/youbot_web/youbot_web.cpp`
- Платформенный ввод-вывод: `controller_io.cpp/.h`
- Mecanum-кинематика и slew limits колёс: `controller_drive.cpp/.h`
- Чистая математика лидара, контекста препятствий и уверенности трассы:
  `controller_lidar_math.cpp/.h`
- Локальное уклонение: lidar-классификация — `controller_avoidance_detection.cpp/.h`,
  выбор стороны и команда движения — `controller_avoidance_command.cpp/.h`, состояние,
  progress/stuck и detour-геометрия — `controller_avoidance_state.cpp/.h`.
- Чистый анализ RGB-кадра, camera obstacle observation и геометрия точек карты:
  `controller_camera.cpp/.h`
- Хранение и объединение camera obstacle/free-space ячеек:
  `controller_camera_map.cpp/.h`
- Чистые растровые примитивы виртуальной камеры:
  `controller_camera_render.cpp/.h`
- Чистые геометрические примитивы Mapping Survey:
  `controller_survey_geometry.cpp/.h`
- Состояние и повторяющиеся переходы Mapping Survey:
  `controller_survey_state.cpp/.h`
- Расписание периодических lifecycle-задач:
  `controller_lifecycle.cpp/.h`
- Тестируемый порядок выполнения одного controller step:
  `controller_step.cpp/.h`
- Математика навигации: `controller_math.cpp/.h`
- Загрузка и расчёт профиля движения: `controller_motion_profile.cpp/.h`
- Загрузка маршрута: `controller_route.cpp/.h`
- Чтение runtime-команд: `controller_runtime_command.cpp/.h`
- Сериализация телеметрии: `controller_telemetry.cpp/.h`
- Общие структуры и enum-типы контроллера: `controller_types.cpp/.h`
- Парсинг ограничивающих зон и покрытий: `controller_zones.cpp/.h`
- Сборка контроллера: `webots/controllers/youbot_web/build_youbot_web.bat`
- Runtime state хранится в корневом каталоге `web_state/`.

## Как это связано с UI

1. `Dashboard.jsx` строит маршрут
2. UI отправляет маршрут в `ws://127.0.0.1:9002/ui`
3. `ws-bridge.cjs` сохраняет маршрут в `web_state/route.csv`
4. Контроллер `youbot_web` в `Webots` читает `route.csv` и ведет робота по точкам
5. Контроллер пишет телеметрию в `web_state/robot_state.json`
6. `ws-bridge.cjs` читает этот файл и рассылает телеметрию в UI через `ws://127.0.0.1:9001`

## Запуск

1. Собрать native solver:
```powershell
npm run native:build
```

2. Собрать контроллер Webots:
```powershell
cd webots\controllers\youbot_web
.\build_youbot_web.bat
```

3. Запустить bridge из корня проекта:
```powershell
npm run bridge
```

4. Запустить UI:
```powershell
npm run dev
```

5. В `Webots` открыть мир:
Открыть `webots/worlds/youbot_only.wbt` из текущего checkout.

6. Нажать `Run`

После этого:
- расставляешь точки в UI
- строишь маршрут
- отправляешь маршрут
- `youBot` должен поехать
- позиция робота должна вернуться на карту в UI

## Захват и перенос

В мире есть физическая коробка `PICK_BOX` размером 30 × 30 × 80 мм, массой 40 г,
с центром `(0.4, -0.1, 0.04)` м. После старта робот стоит и ждёт команды.
В правой панели dashboard раздел «Манипулятор»: оставьте `PICK_BOX` и цель
`X=0.4`, `Y=0.1`, `Z=0.04`, затем нажмите «Взять и перенести».
Z задаёт высоту **центра объекта**, все координаты мировые и выражены в метрах.
Для возврата коробки задайте `Y=-0.1`.

Контроллер раскрывает пальцы, подводит руку сверху, захватывает, проверяет подъём,
переносит, опускает, отпускает, отводит и складывает руку в транспортное положение.
Миссия завершается после подтверждения складывания датчиками: вытянутый захват
иначе пересекает плоскость лидара и заставляет навигацию обходить саму руку.
Переходы используют датчики суставов
и пальцев, а удержание проверяется по фактическому положению объекта в симуляции.
Supervisor используется для наблюдения, объект не телепортируется.
Миссии проходят через общий журнал: повтор после потерянного ACK не дублирует захват,
конкурирующая навигация блокируется. Кнопка остановки прекращает движение руки,
сохраняя захват. После остановки с грузом не перезапускайте мир, если нужно сохранить
физическое состояние груза; новая операция начинается с раскрытия пальцев.

Если обе точки доступны, перенос выполняется при неподвижной базе. Для дальних
объектов и целей база автоматически подъезжает, рука поднимает груз, база
перевозит его и останавливается для размещения. Например, `X=1`, `Y=1`, `Z=0.04`
запускает доставку коробки в эту мировую точку. Новая команда для навигации не нужна.

Доставка остаётся одной миссией с тем же ID до отвода руки. Скорость базы ограничена
0.16 м/с при подъезде и 0.10 м/с с грузом, с учётом меньшего лимита профиля.
Ориентация базы сохраняется; путь рассчитывается на сетке 0.2 м. Запас 0.53 м
вокруг центра базы учитывает выступающую руку и небольшой груз. Проверяются
запрещённые зоны и физические препятствия мира Webots с boundingObject Box,
Cylinder или Sphere. Для неизвестной геометрии доставка отклоняется.
Занятое место назначения проверяется до захвата, ближайший сегмент пути — при
движении. При новом препятствии робот останавливается с ошибкой.

Отмена перевозки останавливает колёса и суставы, сохраняя усилие сжатия захвата;
контакты пальцев могут немного перераспределяться. Не перезапускайте мир с грузом
в воздухе, если нужно сохранить его физическое состояние. Автоматическое
продолжение отменённой доставки пока отсутствует; новая операция раскрывает захват.

Поддерживаются небольшие объекты, доступные для верхнего захвата на плоском полу.
Высота цели должна позволять размещение и отвод руки; таймаут каждого этапа руки —
12 секунд времени симуляции. Планирование обхода препятствий рукой и распознавание
произвольных объектов камерой не добавлялись. Для выбора объекта используется DEF;
Supervisor читает координаты и геометрию мира, движения выполняют моторы и физика.

Проверка в настоящем Webots (SDK, собранный контроллер и native solver должны быть доступны):

```powershell
npm run webots:build
npm run test:manipulator:def
```

Проверяются физический перенос и возврат, отказ для недостижимой цели и отсутствующего
объекта, остановка руки с сохранением захвата. Результаты сохраняются в
`output/manipulator-smoke/manipulator-physics.json`.

Физические сценарии мобильной доставки:

```powershell
node scripts/manipulator-smoke-test.mjs --mobile --near-object --inject-route
node scripts/manipulator-smoke-test.mjs --mobile --obstacle
node scripts/manipulator-smoke-test.mjs --mobile --blocked
```

Проверяются доставка в (1,1), подъезд к удалённому объекту с объездом препятствия,
возврат, отмена во время перевозки и отказ для занятого места назначения.

Регрессия перехода от переноса к навигации:

```powershell
node scripts/manipulator-smoke-test.mjs --route-after-delivery
```

Выполняется перенос, затем полный маршрут из 100 точек. Результат сохраняется
в `output/manipulator-smoke/route-after-delivery-100.json`.

Во время активного захвата или переноса контроллер игнорирует изменения `route.csv`,
чтобы маршрут не перехватывал управление платформой. Такой маршрут не запускается
после завершения переноса: отправьте новую команду явно.
Регрессионная проверка этого сценария:

```powershell
node scripts/manipulator-smoke-test.mjs --inject-route
```

Её результаты сохраняются отдельно в
`output/manipulator-smoke/manipulator-route-interlock.json`.
Проверка также записывает чужие команды обследования и захвата в runtime-очередь:
активная рука отклоняет их, сохраняя возможность отмены текущей миссии.
